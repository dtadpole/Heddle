# DSH Context Assembly, Retention, Compaction and Token Budgeting

Paths are relative to `/Users/zhenc/.volta/tools/image/packages/@deepseek-ai/dsh/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/` (abbreviated `<pkg>`); line numbers are from the shipped `lib/*.js`. Runtime fact: the shipped `standard` preset (`dsh-agent-presets/presets/standard/agent.cordis.yml`) mounts `compaction-basic` with **no** config (so every default below applies) and `tool-result-pruner` with the explicit defaults `8192/4096/1024`.

## 1. Building one model call's message list

There is no separate context-assembly module; the request *is* the derived surface plus the logged header: `{ ...header.config, messages: session.deriveMessages(), ...header.tools, sessionId, signal }` (`ReactLoopAgent.buildRequest`, `dsh-agent-loop/lib/index.js:1166-1218`). The system prompt is **not** a request field — `validateSessionEventData` rejects `header.system` (`dsh-session/lib/index.js:237`) — it is a `system/message` surface node.

Per-step order (`agent-loop:885-908` preStep, `:1008-1124` step): **(1)** `inbox.claim(target)` takes queued next-step input plus one user prompt (the inbox is itself a session projection driven by `agent/inbox/spliced` events). **(2)** `await ctx.systemPrompt.assemble(assembleContextFor(agent, signal))` → `PromptAssembly`. **(3)** `renderContextSections(assembly)` + `RuntimeContextProjection.project(...)` → one optional sourced `user/message` runtime-context snapshot. **(4)** **`agent/pre-step` waterfall** — the single pre-request hook: `compaction-basic` runs its `pressure` check here (`compaction-basic:798-811`) and `dsh-agent-instructions` re-enters here to splice its baseline after the claimed messages (`agent-instructions:1270-1288`). **(5)** `prepareRequest()` — **`agent/request` waterfall**, then `ctx.llm.prepareCall(config, signal)` (`agent-loop:1127-1164`); this runs *after* pre-step, so pre-step compaction changes what is derived. **(6)** `SystemPromptProjection.project(renderPrompt(assembly), {inHistory, startsSeries})` emits ordered `system/message` commits: `append` when none exists, else per-node `{op:'replace',startSeq,endSeq}` head rewrites plus logged empty replacements of stale later system nodes (`agent-loop:216-297`, `:1019-1027`). **(7)** First attempt only: `session.append('user/message', message, {surfaceOp:'append'})` for the accepted batch (`:1028`). **(8)** `buildRequest()` logs `request/header` (first/changed/series) and `request/context` (provider, model, `contextWindow`, `systemPromptUpdate`) when they differ, then calls `session.deriveMessages()` and deep-freezes the request. **(9)** `preparedCall.stream(request) ?? ctx.llm.stream(request)`. **(10)** Terminal failure → **`agent/request-error` waterfall**; overflow recovery returns `{kind:'retry'}` and the `while(true)` loop restarts at step 5 (assembly is not repeated; `firstAttempt` is already false).

Ordering conclusion: `deriveMessages` is the substrate; pruning and compaction mutate the log/surface *before* derivation; instructions and injected context are ordinary surface appends that also precede derivation. There is no post-derivation truncation step.

## 2. Compaction

**Contract.** `ctx.compaction` = abstract `CompactionEngine extends Service` (`dsh-compaction/lib/index.js:172-176`), one per context. Operations: `compactIfNeeded(agent, trigger, signal)`, `compactNow(agent, signal, sourceCommandId)`, `compactRegion(start, end, agent, signal)`. `CompactionResult` (`dsh-compaction/lib/types/types.d.ts:102-131`): `compactionId`, `startSeq`, `summarySeq`, `endSeq`, `summary`, `shadowedRange{start,end}` (a surface *position* span, so `start` may exceed `end`), `shadowedSeqs[]`, `shadowedTokenCount`.

**Triggers** (`dsh-compaction-basic/lib/index.js`): automatic step pressure via `ctx.on('agent/pre-step', ...)` → `compactIfNeeded(agent,'pressure',signal)` (`:798`, `:873-920`), gated on `measurement.totalTokens >= spec.thresholdTokens`; provider-confirmed overflow via `ctx.on('agent/request-error', ...)` when `failure.code === CONTEXT_WINDOW_EXCEEDED_CODE`, bypassing threshold and the retention floor with `selectCompactableRange(..., 0)` and returning `{kind:'retry'}` only after `surface.replaceGeneration` advances (`:820-846`); explicit `/compact` (`dsh-command-compact/lib/index.js`) → `compactNow(...)`, idle-only, also `selectCompactableRange(..., 0)` (`:944-970`), with no model-facing compaction tool; plus `compactionRetries` extra attempts while pressure remains (`:907-918`).

**What it produces.** Not a rewritten log and not a replaced-prefix object: five durable appends (`compactSurfaceRegion` `:433-505`; `commitCompactionBody` `:599-646`) with exactly one surface mutation: `compaction/start` (log-only lock) → `compaction/summary` (log-only: `summary`, `rawOutput`, `shadowedSeqs`, `shadowedTokenCount`, `provider`, `model`, `maxTokens`, `usage`) → `user/message` carrying the framed summary with `surfaceOp:{op:'replace',startSeq,endSeq}` and `sourceEventSeqs:[startSeq, summarySeq, ...shadowedSeqs]` → `compaction/end` (log-only unlock). Replacement content = `CHECKPOINT_PREAMBLE\n\n<compacted-summary>` + summary + `</compacted-summary>` (`:210-257`, `frameSummary` `:323-335`); source = `compactCheckpointSource(compactionId)` = `{kind:'plugin', plugin:'compact', compactionId}` (`dsh-compaction/lib/index.js:109-133`).

**Where stored.** All five events go into the append-only session log, and the summary *becomes* the surface node; shadowed events remain in the raw log, so replay is exact and resume/fork reproduce the same conversation. A summary that does not shrink is rejected (`framedSummaryTokenCount >= shadowedRouteTokenCount`, `:571-572`). The summarizer replays `deriveEventMessage(node 0)` + `header.tools` + shadowed-region messages, then appends `COMPACTION_INSTRUCTION` as the final user message with `GenerateOptions.purpose='compaction'` and `maxTokens` (`buildSummarizationInput` `:666-675`, `summarizeWithLlm` `:269-317`), so the aux call is a genuine prefix of the last routed request (KV reuse); only returned text enters the checkpoint.

**Range selection** (`selectCompactableRange` `:393-416`): start at the first non-`system/message` surface node (the node-0 system head is never shadowed); walk the tail accumulating `nodes[].tokens` until `>= retainTokens`; then decrement `keepFromIdx` while `toolPairingBalancedBefore(...)` is false, so no assistant `tool-call` is split from its `tool/result` (`dsh-compaction/lib/index.js:80-93`). Returns `null` when nothing safe remains.

## 3. Pruning

`ctx.toolResultPruner` = `ToolResultPruner extends Service` (`dsh-compaction-tool-result-pruner/lib/index.js:61-195`), `static inject = ['tokenMeter']`. **Pruned first:** `tool/result` surface nodes whose summed `text` code points exceed `thresholdChars` (default `8192`); `pruneContent` keeps `headChars` (default `4096`) + `PRUNE_MARKER = "\n\n[... tool result middle pruned ...]\n\n"` + `tailChars` (default `1024`), with the config invariant `headChars + marker + tailChars <= thresholdChars` and slicing by Unicode code point so surrogate pairs never split.

**Never pruned:** non-`text` blocks (kept in original relative order and position), any result already within budget, and the system prompt — session-level `assertSystemHeadRewrite` forbids a non-`system/message` replacement over node 0 (`dsh-session:379-383`), and compaction never shadows node 0 either.

**Tool-result treatment:** the original event stays in the log; a new `tool/result` is appended with identical data except `content`, carrying `surfaceOp:{op:'replace',startSeq:seq,endSeq:seq}` and `sourceEventSeqs:[seq]`. Session validates content-only rewrites (`assertToolResultRewrite`, `dsh-session:346-372`). Immediately before each replacement a log-only `compaction/prune` records `shadowedRange`, `shadowedSeqs`, and `shadowedTokenCount = ctx.tokenMeter.estimateMessage(original)` — the shared shadow-price protocol (`:162-180`).

**When:** only after a compaction trigger qualifies (pressure or overflow), before range selection; below-pressure conversations are untouched. Pruning makes no model call, and if it clears pressure, summarization is skipped (`compaction-basic:901-905`). Separately, `dsh-spill-policy` (opt-in `maxInlineBytes`, UTF-8) replaces oversized plain-text results with a head/tail preview from `dsh-output-retention`'s `TextRetainer` plus a retrievable locator, before the result ever becomes history.

## 4. Token accounting

One service `ctx.tokenMeter` = `TokenMeter extends Service` (`dsh-token-meter/lib/index.js:608`, `static inject = ['sessionProjections']`, empty config — any key throws). It makes no model calls; it keeps one replay fold per session (`_sync`/`_foldEvent` `:707-772`).

**Local estimate** (`dsh-token-meter/lib/types/estimate.js`): `CHARS_PER_TOKEN = 4`, `BLOCK_OVERHEAD = 4`, `ROLE_OVERHEAD = 4`. `text`/`reasoning`: `ceil(len/4)+4`; `tool-call`: `ceil(name/4)+ceil(arguments/4)+4`; `tool-result`: recursive content + 4; unknown/image: `4 + ceil(JSON.stringify(block).length/4)`; system: `ceil(chars/4)+4`; tools: `ceil(JSON.stringify(header.tools).length/4)+4`.

**Provider usage** is preferred only when reusable: the anchor's canonical header must equal the measured header **and** `usageTokens(usage) >= estimatedAnchorTokens`, where `usageTokens = inputTokens + (cacheReadTokens ?? 0) + (cacheWriteTokens ?? 0) + outputTokens` (`:594-597`, `:643-686`); otherwise the baseline is `kind:'estimated'`. `totalTokens = max(0, baseline.tokens + surfaceDeltaTokens)`; `nodes[].tokens` is route-priced while `nodes[].heuristicTokens` is route-independent and supplies shadow prices.

**Constants in code** (`compaction-basic`): `DEFAULT_THRESHOLD_RATIO = 0.8`, `DEFAULT_RETAIN_RATIO = 0.16`, `maxTokens = 8192`, `compactionRetries = 1`, `maxOverflowRetries = 1`, `auto = true`. Budgets are `thresholdTokens = floor(contextWindow * thresholdRatio)` and `retainTokens = floor(contextWindow * retainRatio)` or an absolute value; validation requires `retainRatio < thresholdRatio` at load and `retainTokens < thresholdTokens` per model (`resolveCompactSpec` `:108-126`). Capacity comes from the adapter owning the durable route: `(await ctx.llm.resolveModelInfo(provider, model, signal)).context.contextWindow` (`:895`, `dsh-llm/lib/types/types.d.ts:292`), with DeepSeek `DEFAULT_CONTEXT_WINDOW = 1e6` (`dsh-llm-deepseek:1392`). Pruner `8192/4096/1024`; instructions `maxBytes = 65536`, `maxSourceBytes = 1_048_576`.

**UI projections** registered by `TokenMeter`: `tokenUsage` (`uncachedInputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens`), `contextPressure` (optional `pressureTokens`, `projectedTokens`, `contextWindow`), `contextBreakdown` (`systemTokens`, `toolsTokens`, `messageTokens`). These are heuristic and last-wins-per-moment, explicitly not a billing record.

## 5. System prompts and instructions

**Sections** come from `ctx.systemPrompt.section({name, order, text})`, ordered ascending by `order` then code-unit name. Harness identity sits at order `-1000` (`You are an AI agent powered by DeepSeek Harness.`), persona prefix `0`, harness source `10000`, Web surface `10100`, persona suffix `10200`; `complete: true` replaces the whole prompt. `ctx.systemPrompt.variable(name, provider)` supplies `{{name}}`, and the loop supplies `provider`, `model`, `cwd` (`agent-loop:1534-1536`).

**Assembly:** `assemble()` merges global plus agent-scope layers, detaches tool parameters, canonicalizes order, runs the scope-filtered `system-prompt/assemble` waterfall and applies runtime-context suppressors; `renderPrompt()` interpolates, drops empty sections and joins with blank lines. Tool schemas are part of the same assembly (`toolOrder` canonicalization), and per-agent `ctx` registrations shadow same-named globals.

**Injection:** the rendered prompt becomes the `system/message` surface node — appended when absent, otherwise rewritten in place; with `systemPromptUpdate: 'in-history'` in a continuing request series a changed prompt is appended after the cached history. An empty rendering clears every non-empty system node with logged empty replacements, so no older prompt stays model-visible.

**Per-project instruction files** (`dsh-agent-instructions`, a plain `apply(ctx, config)` plugin, `inject = ['sessionProjections']`): at the first eligible `agent/pre-step` it composes one durable user-role baseline message. The project root is found by climbing until a `projectRootMarkers` probe (`['.git']`) is absent; the chain is the user-global `$DSH_HOME/AGENTS.md` (or `~/.dsh/AGENTS.md`) followed by every existing candidate from root down to `session.header.cwd`, broad → specific. Base candidates `['AGENTS.md','CLAUDE.md']`, local overlays `['AGENTS.local.md','CLAUDE.local.md']`, and content-identical (trimmed SHA-1) siblings render once. The required `maxBytes` (65536 in `standard`) caps the rendered message: broader files are dropped whole before the most-specific file is truncated, and a `Workspace instruction budget ...` notice names the omissions. Delivered as a `<system-reminder>`-framed `user/message` with `source.kind = 'agent-instructions'`, `baseline`, `baselineIdentity`, `changes`.

**Refresh:** no watcher. Successful first-party `read`/`write`/`edit` results are tracked (`tools/result`, `exec.arguments.file_path`, bubbling through `exec.parent`), projected after the enclosing `step/end`, and reconciled into the inbox; changed files replace, disappeared or duplicate files produce a removal notice. An unchanged path plus digest is never re-injected, and shell `cd` does not trigger discovery.

**Per-preset composition:** `dsh-agent-presets` mounts one standing Cordis composition per preset id from `agent.cordis.yml` (shipped `standard`/`ptc`/`cordis`/`minimal` plus `<dshHome>/.agent-presets`), so which prompt sections and tools exist is decided once, before the agent is published (prefix-stable for its life). `dsh-agent-default-model` only supplies the `provider`/`model`/`reasoningEffort` default under the settings namespace `agent-default-model`.

## 6. "Projection": two distinct meanings

**(a) Message projection.** `deriveEventMessage(event)` (`dsh-session/lib/types/surface.js:75-83`, re-exported at `dsh-session/lib/index.js:209`): `user/message` → `event.data`; `system/message`/`assistant/message` → `event.data.message` unless `content.length === 0` (then `null`); `tool/result` → `event.data.message`; everything else `null`. `Session.deriveMessages()` (`dsh-session:1269-1284`) folds it over `surface.nodes`. **Cache:** a `derived` array plus `derivedNodes` and `derivedGeneration`. **Invalidation:** a rewrite bumps `surface.replaceGeneration` (`applySurfacePlan`, `dsh-session:410-415`) and the cache is dropped when `replaceGeneration !== derivedGeneration`; appends cost O(new nodes) and a replace rebuilds. The returned array is fresh per call while the messages are shared and deep-frozen.

**(b) Session projection registry.** `ctx.sessionProjections` = `SessionProjectionRegistry extends Service` (`dsh-session-projection/lib/index.js`, types at `lib/types/index.d.ts:134-291`). A `ProjectionDefinition` is `{key, stateSchema, stateVersion, init, apply, wire?}`; the registry subscribes to `session/event` once and eagerly passes every committed event through every unit's synchronous `apply`. **Caches:** per-session cells (state plus watermark seq) and a two-slot raw-view cache; a client-visible key publishes only when `wire.view` changes by `Object.is`. **Invalidation:** a `stateVersion` mismatch discards persisted rows (`checkpoint`/`restoreFloor`/`restore`, `ProjectionCheckpointRow{ver,seq,val}`); registration is an effect on the calling fiber, so unloading a plugin removes its key and cells; a shrunken log is detected by the one-below `restoreFloor` anchor. `dsh-session-projection-cache` persists rows at `<root>/session_projcache/sessions/<id>.json`, writes mandatorily at session creation, `turn/end` and disposal plus `writeEveryEvents`/`writeIntervalMs` throttles, and may lag the log (the log leads, the cache follows). Consumers use `snapshot()` → `{asOfSeq, values}`, `stateOf(session,key)` and `onChanged(listener)`.

## Minimum viable reimplementation

1. **Append-only event log plus a positional surface.** Keep every event; maintain `surface.nodes: seq[]` where only the four message-producing types may append and everything else (chunks, boundaries, lock markers) is log-only. This one structure gives retention, replay and compaction without a second copy of history.
2. **One projection function** `event -> Message | null`, folded over `surface.nodes` per request. Cache it, extending on append and rebuilding when a replace bumps `replaceGeneration`; the `system/message` node is the system prompt, not a request field.
3. **A token meter** with a deterministic estimate (`ceil(chars/4)` plus fixed block/role overhead) and an optional provider-usage anchor reused only for an identical envelope; expose `measure(session) -> {totalTokens, nodes:[{seq,tokens}]}`.
4. **Budget resolution** `threshold = floor(contextWindow * 0.8)` and `retain = floor(contextWindow * 0.16)`, requiring `retain < threshold`.
5. **Prune before summarizing:** rewrite over-budget `tool/result` text to `head(4096) + marker + tail(1024)` as a `surfaceOp:'replace'` over exactly that node, then re-measure and stop if pressure cleared.
6. **Compaction:** select the oldest span starting at the first non-system node, leaving a tail priced `>= retain`, cutting only at tool-call/result-balanced boundaries; summarize with one aux call that replays the exact prefix plus the instruction; append `start-marker → summary-record → user/message{surfaceOp:'replace', sourceEventSeqs:[...]} → end-marker`; reject a summary that is not strictly smaller; store nothing outside the log.

Required order, each step consuming the previous step's state: **append input → derive messages from the surface → measure → if over threshold: prune → re-measure → select range → summarize → replace the span → re-derive → send.** Invariants: the range never includes surface node 0 when it is the system prompt; a cut never separates a tool call from its result; the replacement is strictly smaller than what it shadows; and the log retains both the original and the replacement events.
